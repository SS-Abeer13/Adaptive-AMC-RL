# v8 Code Audit — 2026-09-29

Scope: the active v8 pipeline (`Optimized/v8`) and the helpers it pulls in from
`v7` (`generateChannel_v7`), `v5` (`baseCQI_v5`, `schedule_users_v5`,
`schedContext_v5`, `sampleSched_v5`) and `case2_3` (`tbsFromMCSandRB`,
`createTBS_Table`). Pre-audit copies of every edited file are in
`_pre_audit_backup/`. MATLAB was not available, so the non-deep-learning path
was executed end to end in GNU Octave 8.4 (smoke test, calibration, all 7
classical comparators, `runComparison_v8` reporting, `export_v8_text_report`);
the A2C trainer was syntax-checked and its return recursion unit-tested, but it
still needs one real MATLAB run (`test_v8_smoke`).

**Bottom line: every number in `Dataset/results_v8_*.txt`, the v8 figures, the
v8 PDF report and `RESPONSE_TO_REVIEWERS.md` is affected and needs to be
regenerated.** The headline secondary claims (+218 % burst throughput, doubled
Jain fairness, +250 % edge throughput) are produced by bug #1 and disappear
when it is corrected.

## Bugs found and fixed

| # | Severity | File | Problem | Fix |
|---|---|---|---|---|
| 1 | Critical | `runComparison_v8.m` | Metric matrices pre-allocated with **zeros** for all seeds; the 7 deterministic schemes only fill row 1, then `nanmean(X(:))` averaged in the zero rows. With 2 seeds, every non-RL scheme's BLER, edge Tp, Jain, burst and calm Tp was halved. | Pre-allocate with `NaN`; new `metricMean_v8.m` also corrects legacy `.mat` files. Used in `runComparison_v8`, `generate_figures_v8`, `export_v8_text_report`. |
| 2 | Critical | `DeepA2C_Shared_v8.m` | A2C targets were `r + γ·V(S_now)` for **every** buffered transition, where `S_now` was the state at flush time (up to ~200 TTIs later under PF/RR, and the newest transition used its own pre-action state). No n-step return was ever formed. | Per-user returns over each user's scheduled transitions (`G = r + γG_next`), last one bootstrapped from the true successor state; flush moved to after the next state is built; post-episode state used at truncation. |
| 3 | High | `DeepA2C_Shared_v8.m` | HARQ retransmission TTIs were given policy-gradient credit although the sampled action is ignored (retx reuses stored MCS). | Retx transitions stay in the return/critic target but are masked out of the actor loss. |
| 4 | Critical | `defaultEnv_v8.m` | **CQI table off by one level.** CQI *q* is sent as MCS *q−1*, but `CQI_thresholds(q)` was the 10 %-BLER threshold of MCS *q−2*. With perfect CSI and action 0, mean first-tx BLER was **75 %** (max 100 %) instead of ≤10 %. Calibration's "best fixed offset = −1" was just undoing this. (Same defect in v6 and v7.) | Thresholds now `[-Inf, -5.0, -3.2, …, 21.8]` (15 entries); smoke test asserts max BLER ≤ 10 % at action 0 (verified: 0.100). |
| 5 | High | `txStep_v8.m`, `MultiOLLA_v8.m`, `defaultEnv_v8.m` | OLLA offsets were unbounded. ~38 % of user-TTIs are below MCS-0 decodability in this link budget (median SINR −3.2 dB), so integrators wound down indefinitely while pinned at CQI 1. Octave check (6 traces, PF): Warm-OLLA 2.36 Mbps unbounded → 3.43 Mbps with ±10 dB bound. This windup produced the "A2C beats Warm-OLLA by +20 %" result. | New `env.olla_off_lim = 10` (dB) anti-windup clamp; set `Inf` to reproduce old behaviour. |
| 6 | Medium | `MultiOLLA_v8.m` | `env.multi_olla_slow` (0.2 dB) was never used; the "slow" loop ran at the standard OLLA step (0.5 dB). | Slow loop uses `env.multi_olla_slow`. |
| 7 | Low | `evalPolicy_v8.m` | Multi-OLLA's adaptive α was computed for the MCS choice but a constant 0.5 was passed to `MultiOLLA_v8`. | Pass the α actually used. |
| 8 | Medium | `runComparison_v8.m` | Holm–Bonferroni correction was claimed in the design plan and reports but never computed. | New `holmAdjust_v8.m`; Holm-adjusted p printed next to raw Wilcoxon p. |
| 9 | Low | `runComparison_v8.m` | Separator strings were not passed through `sprintf`, so the `.txt` reports contained literal `\n`. | Fixed. |
| 10 | Medium | `export_v8_text_report.m` | Indexed the 1×2 `results.metrics` struct array as a scalar (errors), only handled PF, inherited bug #1 and overwrote the original results file. | Rewritten: loops over schedulers, uses `metricMean_v8`, adds Holm, writes `results_v8_<tag>_recomputed.txt`. Set `tag` before running for other points. |
| 11 | Low | `generate_figures_v8.m` | Fig 6 passed CQI *q* as the MCS index (MCS 0 missing, MCS 14 plotted twice). Figs 2–3 inherited bug #1. | Uses MCS *q−1*; figs 2–3 use `metricMean_v8`. |

## Issues found but NOT changed (need an author decision)

1. **Privileged state information.** `stateFeat_v8` receives the *true* per-user speed (`meta.speeds`), the true (delayed) burst indicator and the true feedback delay, while the design plan describes them as estimates (`v_est`, `b̂`). Classical comparators get none of this. Either add estimators/noise or disclose it as a genie-aided agent.
2. **"Fixed-Online" is not online.** It classifies users with a 20-TTI mean of the *true* speed and the true delay, so it is effectively a causal oracle; the README/response-to-reviewers claim of a "Doppler autocorrelation estimator" is not implemented.
3. **OLLA runs underneath every scheme except Baseline** (`useOLLA = ~baseline`), including Fixed, Fixed-Online, FixedPU and A2C. In steady state the integrator absorbs any fixed offset, which is why Fixed ≈ FixedPU ≈ OLLA in `steady1000`. The "fixed-offset" comparators are really OLLA with a different start point.
4. **Claimed v8 fixes that are not in the code:** OLLA step scaling `δ0/√T` (Fix 3) is absent; the "LSTM/recurrent" A2C (Fix 5) is a 3-frame stacked MLP; HARQ Chase combining is `SINR_now + 2.5·n` dB rather than accumulated SINR (`H.sinr_eff` unused); `env.harq_adaptive` and `env.max_delta = 6` are unused/inconsistent with actions −6…+4.
5. **TOST margin** is ±0.10 Mbps absolute in code vs ±2 % relative in the design plan.
6. **Statistical power.** `run_v8_campaign.m` uses 2 seeds, 30 traces, 50 episodes, while the design plan and reports state ≥5 seeds, ≥100 traces, 300 episodes. Each scheme also gets a different RNG seed for ACK draws, which adds ~5 % Monte-Carlo noise to paired comparisons; common random numbers would tighten them.
7. **Link budget.** 20 dB O2I + 6 dB implementation margin over a 1 km × 1 km area puts ~38 % of user-TTIs below MCS-0; many users are effectively out of coverage, which inflates BLER floors for every scheme.
8. **Warm-up realism.** Warm-OLLA's 1000-TTI warm-up uses an independent channel draw (new positions) seeded only by `(W, N, mean delay)`, so many traces share the same warm-up segment.
