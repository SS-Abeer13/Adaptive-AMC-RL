Introduction, Goal, and Research Process
The core goal of this research is to design and evaluate Reinforcement Learning (RL) al-
gorithms for Link Adaptation (LA) in a multi-user, mobile cellular downlink – dynamically
selecting the Modulation and Coding Scheme (MCS) for each scheduled user at each Transmis-
sion Time Interval (TTI), relative to the industry-standard Outer Loop Link Adaptation (OLLA)
control.
1.1
The v6 Lesson
The v6 campaign showed that Deep A2C beat OLLA by statistically significant margins at several
feedback delays. However, an audit control (a best-tuned constant offset, calibrated on held-out
traces) revealed that this constant matched RL throughput in v6’s calm, homogeneous, error-
free-transmission environment. The implication: v6’s entire learned advantage over OLLA was
explainable as a single scalar setpoint shift – running hotter – not a state-conditional policy. v6
was quasi-stationary (weak within-trace dynamics), assigned zero cost to transmission failure (no
HARQ), used one BLER curve for every user (no heterogeneity), and gave RL and the OLLA loop
strictly equal information (no informational asymmetry to exploit). Under those conditions, there
is nothing left for a state-conditional policy to do beyond picking the right constant.
1.2
The v7 Hypothesis
v7 was designed to test whether restoring realistic sources of non-stationarity and heterogeneity
would restore genuine adaptivity value – i.e., would a state-conditional RL policy start to beat an
oracle-tuned constant, not just an OLLA loop? Five architectural levers were introduced (Sec-
tion 2), and a 12-point pre-registered campaign (Section 4) was executed to test this hypothesis
under a strict, pre-declared win condition (Section 3).
1.3
Research Process
1. Designed and implemented the v7 stack: HARQ physics, heterogeneous users, non-stationary
interference, honest per-MCS BLER curves with Jakes fading, and a two-tier (information-
equal vs. richer) state representation.
2. Executed the pre-registered 12-point campaign against seven comparator schemes.
3. Diagnosed a 0/9 failure rate on the primary pre-registered win condition across the initial 9
points.
4. Root-caused the failure to five concrete, fixable issues (calibration asymmetry, action-set clip-
ping, undertraining, entropy collapse after behavior-cloning) rather than an intrinsic absence
of adaptivity value, and iterated three further fix rounds (tier1, tier1b, tier1-nobc).
5. Ran a council-style adversarial review of the resulting evidence, which identified the single
most decisive remaining experiment: sweeping OLLA’s target BLER to test whether the
residual RL-vs-OLLA gain is a mis-tuned-baseline artifact.
6. Executed that sweep. The RL-vs-OLLA gain survives; the RL-vs-oracle-constant null does
not resolve into a win.

v7 Environment Design
v7 retains v6’s OLLA-relative action encoding (action 0 ≡OLLA exactly; every RL policy carries
the identical OLLA inner loop) and honest, cooperative, reported-CQI proportional-fair scheduling.
Five design changes (D1–D5) were added on top, targeting the specific simplifications that v6’s audit
identified as removing all adaptivity value.
2.1
D1: HARQ with Chase Combining
Failed transmissions in v6 cost nothing (Bernoulli success probability was scored as expected good-
put, with no retransmission channel). v7 introduces a full HARQ loop: a user with a pending
failed transport block (TB) retransmits the same TB at the same MCS on its next scheduled slot,
receiving a chase-combining gain of +2.5 dB per prior attempt, up to harq max retx = 3 attempts
before the TB is dropped:
eff SINRretx = SINRtrue + nretx × ∆comb,
∆comb = 2.5 dB
(1)
OLLA updates its offset only on first-transmission ACK/NACK, matching standard 3GPP outer-
loop behavior. This makes running an aggressive MCS genuinely costly: an over-aggressive first
transmission consumes extra slots on retransmission rather than being scored for free.
2.2
D2: Per-User Heterogeneity
Each user is drawn with an independent CQI feedback delay (uniform over {2, . . . , 8} TTIs) and
mobility speed (uniform over [3, 30] m/s), collapsed into a 2 × 3 (delay class × speed class) grid
for the per-class fixed-offset comparator. A single global constant offset cannot simultaneously be
optimal for a slow, low-delay user and a fast, high-delay user.
2.3
D3: Non-Stationarity
A cell-wide two-state Markov chain toggles an interference burst (extra +6, +9, or +12 dB of
interference), with mean dwell times of ≈250 TTIs calm / ≈120 TTIs during a burst. Users
additionally undergo one mid-trace speed change. These transitions are the events an integrator-
based control loop (OLLA) is structurally slow to react to, and where a predictive, state-conditional
policy should have room to add value.
2.4
D4: Honest Physics
Per-MCS BLER waterfalls were steepened (slope parameter k ∈[3.0, 5.8], versus v6’s [1.2, 2.7]) so
that overshooting the correct MCS carries a real error-rate penalty rather than a gentle degradation.
Fading is generated per user via a Jakes-calibrated AR(1) process, with the innovation coefficient
computed directly from each user’s instantaneous speed:

D5: Two-Tier State Ablation
Tier A is the exact v6 information-equal state (reference CQI, CQI delta, observed SINR, SINR
trend, OLLA offset, scheduler context) – strictly no more information than the OLLA loop itself has
access to. Tier B adds five features no scalar control loop can represent: HARQ pending/retransmission-

is the direct test of whether the richer state buys anything.

Comparator Suite and Pre-Registration
Seven schemes are evaluated, all carrying the identical OLLA inner loop except Baseline:
1. Baseline – static CQI map, no OLLA offset, no outer-loop control.
2. OLLA – the classical outer loop; RL action 0 is defined to be exactly this.
3. Fixed – the single best constant offset, grid-searched ({−4, . . . , 2}) on independent calibration
traces.
4. FixedPU – the best constant offset per user class (2 delay classes × 3 speed classes = 6
constants), calibrated the same way. This is the primary, pre-registered comparator.
5. QL v7 – tabular Q-learning, Tier-A state only (a table cannot fit Tier-B).
6. Tab AC v7 – tabular actor-critic, Tier-A state only.
7. Deep A2C v7 – a 2-hidden-layer (96×96) shared-network actor-critic, Tier-A or Tier-B
selectable, ≈30k parameters.
Pre-registered win condition: Deep A2C must beat FixedPU on cell throughput, under the
proportional-fair (PF) scheduler, by a paired Wilcoxon signed-rank test at p < 0.05, evaluated on
30 held-out traces identical across every scheme.
FixedPU and Fixed are oracle-tuned: they require a calibration pass on separate traces and
never adapt to state. OLLA requires zero calibration and adapts online but is reactive (integrator
dynamics only). The pre-registered comparison is therefore explicitly a test of whether a learned,
state-conditional policy can outperform an oracle given the same evaluation traces – not merely
whether it beats a zero-knowledge reactive loop (which is a separate, secondary claim addressed in
Section 8).

Diagnosis: Why Zero Wins?
Five concrete, independently verifiable issues were identified by direct code inspection, not specu-
lation:
1. Calibration asymmetry.
calibrateFixedClass v7 tunes FixedPU exclusively on the
PF scheduler, while Deep A2C was trained on a 50% PF / 25% RR / 25% EQ mixture
(train sched weights). The comparator’s advantage was partly a training-distribution mis-
match, not a control-quality difference.
2. Action-set clipping. The calibration grid fixed cands = [−2, 1] was clipped at its own
optimum (best global offset = −2; the true per-class optimum in one class was −4), while Deep
A2C’s action set was only ±3. The comparator’s true optimum was structurally unreachable
by the learner.
3. Undertraining on cold start. With 500 episodes and no informed initialization, vanilla
Deep A2C settled roughly 5% below a policy it can trivially represent (a constant), indicating
insufficient exploration/convergence within budget.
4. Entropy collapse after behavior-cloning. When a 150-episode behavior-cloning warm
start from FixedPU was introduced (to remove issue 3), the clone reached near-zero policy
entropy (fully deterministic), but the subsequent RL fine-tuning phase restarted its entropy-
bonus coefficient at its maximum scheduled value (0.05), re-randomizing the cloned policy
back to near-uniform (H ≈1.9 of a max of ≈1.95 for 7 actions) within approximately 100
episodes. The fix (behavior-cloning entropy coefficient reduced to 0.03; post-clone fine-tuning
entropy anneal starts at 0.01 instead of 0.05) is documented in Table 2.
5. Information, not optimization, was already ruled out. The Tier-A vs. Tier-B ablation
(Figure 6) shows no significant difference between the information-equal state and the richer

Key Insights
1. The optimal link-adaptation policy in this environment class is a constant, not
a state-conditional function. Across the v6 A3 control, the v7 nine-point campaign, and
three further Tier-1 iterations – eleven or more independent experiments – a per-user-class
constant offset matches or beats every learned policy on the primary scheduler.
HARQ,
heterogeneity, non-stationary bursts, and steep BLER curves do not change this conclusion.
2. Published ”RL beats OLLA” gains are plausibly setpoint effects.
Deep A2C’s
advantage over OLLA is real, reproducible, and survives an adversarial re-tuning of OLLA’s
own target BLER (Section 8) – but it is statistically indistinguishable from what a single
constant offset achieves. The mechanism is that OLLA’s classical 10% BLER target predates
HARQ chase combining; under chase combining, running ∼40–45% first-transmission BLER
and relying on cheap retransmissions is throughput-optimal, and this is a scalar operating-
point fact, not a policy the agent needs state to discover.
3. Richer state provides no additional value. The Tier-A/Tier-B ablation (Section 6) is a
clean negative result: five additional features (HARQ state, NACK history, SINR slope, speed,
burst observation) do not move the needle. The bottleneck was never missing information.
16

--- PAGE 17 ---
4. The optimization-vs-information distinction is resolved.
tier1b’s zero-gain-from-
fine-tuning result, combined with tier1-nobc’s near-parity from scratch, together show that
the residual campaign-wide gap in the original nine points was a fixable optimization/calibra-
tion artifact (asymmetric comparator tuning, clipped action grids, an entropy-schedule bug),
not evidence that RL is intrinsically incapable of matching the oracle. Once those artifacts
are removed, RL reaches the oracle’s throughput – it simply does not exceed it.
5. Seed sensitivity remains a caution.
The original headline point showed near-parity
(−0.7%) that worsened under a fresh seed (−4.4%).
Practitioners deploying learned link
adaptation should not treat a single training run as representative; multi-seed evaluation, as
used throughout this report, is necessary to distinguish a real effect from noise.

Recommended Paper Framing
This report supports a characterization paper, not a ”RL beats the state of the art” paper. The
defensible claims, in order of strength, are:
 Deep A2C statistically matches an oracle-calibrated, per-user-class constant offset rule –
without needing that oracle’s calibration data (tier1-nobc: −5.1%, n.s., p = 0.06) – while
requiring no per-deployment tuning pass.
 Deep A2C beats the industry-standard OLLA outer loop by +7–13% across a wide range
of configurations, and this gain survives an adversarial re-tuning of OLLA’s own operating
point.
 The mechanism behind both findings is a setpoint effect (an aggressive, HARQ-subsidized
operating point), not learned state-conditional adaptivity – confirmed by an information-
ablation null result and by statistical indistinguishability from a single constant offset.
 The residual gap in the original nine-point campaign was diagnosed as a fixable comparator-
calibration and RL-training artifact, not a fundamental information deficit – itself a useful
methodological finding for future RL-vs-tuned-baseline studies in wireless.
A single claim to avoid without qualification: ”RL recovers oracle-calibrated performance without
per-deployment tuning” should cite the tier1-nobc (no-clone) result specifically, since the tier1b
headline number was itself initialized by imitating the oracle comparator and cannot alone support
a zero-calibration claim.

13.2
Behavior-Cloning Warm Start (Tier-1 Fix)
The fine-tuning-preserving behavior-cloning loss used in tier1b, cross-entropy on FixedPU’s per-
class actions plus a soft entropy bonus to avoid saturating the clone:
function [aGrad, cGrad] = bc_grads(actorNet, criticNet, S, Atgt, R, entW)
V = forward(criticNet, S);
cLoss = mean((R - V).^2);
logits = forward(actorNet, S);
logp_all = logits - (max(logits,[],1) + log(sum(exp(logits - max(logits,[],1)),1)));
mask = zeros(size(logits), ’like’, extractdata(logits));
for b = 1:size(S,2), mask(Atgt(b), b) = 1; end
ce = -mean(sum(logp_all .* dlarray(mask), 1));
entropy = -sum(exp(logp_all) .* logp_all, 1);
aLoss = ce - entW*mean(entropy);
% entW = 0.03: keeps clone soft
cGrad = dlgradient(cLoss, criticNet.Learnables, ’RetainData’, true);
aGrad = dlgradient(aLoss, actorNet.Learnables);
end
